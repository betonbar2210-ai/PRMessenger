# PRMessenger

## Отправка рассылок по расписанию

Рассылка с заданным `start_at` уходит сама, **но только если запущен
планировщик**. Django сам ничего не отправляет по таймеру: код работает
тогда, когда выполняется запрос или команда. Поэтому «отправку по времени»
должен кто-то регулярно проверять.

### Вариант 1. Постоянный процесс (для разработки)

В отдельном окне терминала:

```
python manage.py send_mailings --watch --interval 30
```

Команда проверяет базу каждые 30 секунд и отправляет все рассылки, у которых
наступил `start_at`, срок ещё не истёк и которые не отключены менеджром.

### Вариант 2. Планировщик ОС (для продакшена)

Однократный запуск, который повторяет система:

```
python manage.py send_mailings
```

### Как это работает

* `get_due_mailings()` — рассылки со статусом «Создана», у которых наступил
  `start_at` и не истёк `end_at`;
* `claim_mailing()` — атомарно переводит рассылку в «Запущена» под блокировкой
  строки, поэтому забрать её может ровно один процесс: планировщик и кнопка
  «Отправить» не удваивают письма;
* `update_statuses()` — закрывает окно рассылки, когда `end_at` прошёл.

Кнопка «Отправить» отправляет рассылку независимо от расписания, но
использует тот же `claim_mailing()`, поэтому повторное нажатие и совпадение с
планировщиком не приводят к дублям.

### Важно

Процесс планировщика должен быть запущен, иначе рассылки по времени будут
копиться в статусе «Создана» до нажатия кнопки. Если процесс прерван в
момент отправки, рассылка останется в статусе «Запущена» и повторно уже не
отправится — это осознанное ограничение: возобновление с места падения требует
очереди задач (Celery), которая здесь не используется.
